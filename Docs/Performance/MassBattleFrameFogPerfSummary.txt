MassBattleFrame fog performance acceptance

Old 9,944-unit and 29,352-source numbers measured obsolete pipelines and are
not valid evidence for the current implementation.

Current invariants:

0. FogOfWar injects processor ownership before CDO construction and audits the
   frozen Mass phase list. A failed audit is fatal; there is no runtime
   ownership switch or dual-writer mode.
1. FogOfWar replaces only MBF's Agent Render processor without modifying MBF.
   Fresh final-mask revisions maintain
   stable proxies and ActiveProxyIds. Render and simulation sub-frames both
   execute the heavy presentation query only for an Active Mass entity
   collection. Combat and movement simulation remain owned by MBF's logical
   processors.
2. A source request and the matching final-mask revision share one refresh.
   World-scale source collection uses one narrow, contiguous Mass query that
   also admits visible units; camera-only refreshes use the occupied HashGrid.
   There is no source-only or second spatial traversal.
3. One compact source buffer is uploaded at 24 Hz and shared by two binary,
   blend-disabled GPU draws. The high-resolution PF_G8 visual mask uses exact
   source positions/radii at 24 Hz. The HashGrid-aligned PF_G8 logic mask keeps
   the existing exact radius and only changes its cadence to 3 Hz; it writes
   0=hidden or 3=true vision. There is no second CPU traversal or source upload.
4. Scene display projects the cached visual mask with exactly one instance and
   performs one SceneColor composite per render frame. It never redraws source
   circles per render frame, so the ordinary render-frame cost is independent
   of source count. There is no Landscape/decal/material path.
5. Only the 3 Hz logic mask drives an asynchronous readback. At most one staging
   copy may be in flight; no readback backlog is allowed.
6. Deep-fog, state-1 and camera-external units are absent from all effective
   presentation submissions. They write no hidden VAT prewarm element and create
   no Actor instance. Only final state-2/3 units enter a backend.
7. Attack exposure and AlwaysFogVisible upgrade one unit to state 2 only; they
   never mutate the terrain texture or reveal nearby units.
8. RememberLastSeen stores a building payload only while it is in state 3.
   Particle VAT can replay that frozen payload in state 2. Actor stays hidden
   because no frozen backend exists yet; it never reads live hidden
   state.
9. The 3 Hz all-world minimap snapshot uses a separate, low-frequency read-only
   query. It does not route N agents through LOD, VAT animation, interpolation
   or Niagara packing.
   Vision providers form a prefix; fog-visible policy/attack markers use a
   separate dark-marker GPU batch and never touch the vision stencil.
10. ProxyPool and FVisualizing interpolation state remain stable. InstanceId is
    a per-frame dense destination; heavy arrays are written once at their final
    location, retain Capacity, and are never produced sparsely then compressed.
    UE::Mass::FEntityCollection caches the Active handles and version-checks its
    archetype ranges; it rebuilds only on membership or entity-order changes.
    Stable frames do not rewrite the handle list. The Particle dense layout is
    cached per subtype and rebuilt only for membership/renderer changes or after
    a simulation-tick representation transition. Ordinary render frames perform
    no per-proxy FVisualizing discovery or slot-remapping pass.
11. FogOfWar's processor takes the original FrameEnd name/order. With no active
    scene Fog actor it delegates directly to MassBattleFrame's real Execute;
    a placed actor always activates the new path. Missing prerequisites are
    fatal rather than falling back to a full population. Its VAT/Actor query
    runs only for the final visible collection.
    VAT consumes dense arrays and Actor uses delta-sized spawn/recycle commands.
12. CSV stats FogMassBattleRender/ActiveProxies, ActiveHandleListRebuilt,
    WorkSetRefresh, FullWorkSetConvergence, SpatialCandidates,
    FogVisibilityTests, UploadedElements and MinimapSnapshotAgents make the VAT
    complexity boundary observable. UploadedElements must track visible work,
    not total N or historic S; the separate MinimapSnapshotAgents count is allowed to track
    total N only at its 3 Hz request rate.
